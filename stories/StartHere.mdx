# Improvement Map UI catalog

Find an existing solution before designing or implementing another one. These are production Vue components, rendered with deterministic fixtures.

**Pilot status: Draft.** Publication documents current behavior; it does not imply design approval. Test results are advisory during adoption.

The earlier pilot documentation and examples live under **REFERENCE**: Start here, Foundations, Components, Patterns and Screens. Shared bars live under **BARS**, new button designs under **BUTTONS**, containers under **CONTAINERS**, and inputs and composed fields under **FORM**. The standalone **Colors** page defines the shared palette.

Use the theme toolbar and Controls to explore states. Story links are suitable for issues and design requests. The **Code** panel shows usage; source contracts document required context and events.

Component previews are fullscreen and show the raw component without a decorative card, added spacing or width wrapper. Backgrounds, grid and outlines are toolbar tools. Component-owned spacing, borders, shadows and backdrops remain visible. Idea rows keep only their required unstyled list parent. Slot examples identify supplied content; opener and other multi-component examples belong under Patterns. A closed component can produce an intentionally blank preview.

## Contribution workflow

1. Find a matching component and read its contract and stories.
2. Reuse it or extend a documented variant. Use slots for content composition.
3. If no pattern fits, record the missing responsibility before adding a component.
4. Add realistic states and interaction checks alongside the implementation.
5. Review in light/dark themes, narrow and desktop widths, and with keyboard navigation.
6. Ask a maintainer to review the pattern and its visual evidence. Record approval in the component index before changing its tag from Draft to Approved.

**Status:** Draft = available for review; Approved = reviewed for reuse; Deprecated = use the documented replacement. Questionable existing behavior is recorded as `needs-intent-confirmation`, with evidence. Do not silently redesign it during extraction.

## Public sandbox

Browse examples use in-memory bookmark/storage replacements, memory routing, and a fixture workspace. They do not submit ideas, load Google Maps, request GPS permission, or modify application bookmarks. Use the application tests for persistence, navigation history, data sorting, map lifecycle, and real integration behavior.

The catalog is published with the app. The brand link returns to the app. Local development: `npm run storybook`. See the repository's `docs/storybook.md` for tests, deployment, and optional local MCP access.
